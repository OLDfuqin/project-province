# 军队自定义招募、编号、更名与合并设计

## 1. 目标

本次更新把当前固定招募1000人的界面改为玩家输入招募数量，并为军队增加面向玩家的国家代号与本国编制编号。同时增加军队编号修改和同地多军合并，使军队管理具备后续扩展师、军、集团军等层级所需的稳定身份基础。

本次仍只有一种陆军，不增加兵种、装备、拆分、组织度、补给或军队维护费。

## 2. 核心设计原则

### 2.1 稳定 ID 与显示编号分离

军队继续使用不可修改的内部稳定 ID，例如 `army_1`。移动、战斗、推进计划、存档引用和 Godot 选择状态都使用稳定 ID。

每支军队新增正整数编制编号 `formation_number`。玩家看到的名称不保存为独立字符串，而是根据军队所属国家和编制编号组合：

```text
显示名称 = 国家代号 + “·第” + formation_number + “军”
```

例如：`奥·第1军`、`凯·第3军`。

玩家更名只修改 `formation_number`，不会改变军队稳定 ID。因此更名不会使移动选择、自动推进计划或其他对象引用失效。

### 2.2 编号唯一性

- 编制编号必须是正整数。
- 编制编号只要求在同一个国家的现存军队中唯一。
- 不同国家可以同时拥有第1军。
- 招募新军队时，从1开始寻找该国当前未使用的最小正整数。
- 军队被消灭或因合并被删除后，其编号立即成为空缺。
- 后续招募可以复用最小空缺编号。

## 3. 国家代号

国家初始数据新增不可为空的 `code` 字段。首个剧本使用以下固定单字代号：

| 国家 | 稳定 ID | 代号 |
| --- | --- | --- |
| 奥罗里亚 | `auroria` | `奥` |
| 凯洛斯 | `caelus` | `凯` |
| 索尔梅尔 | `solmere` | `索` |
| 维丹提亚 | `verdantia` | `维` |

同一剧本中的国家代号必须唯一。场景加载和存档加载均校验代号非空与唯一性。

国家代号属于数据驱动的显示属性，不作为国家稳定 ID，也不参与外交、领土或所有权判断。

## 4. 自定义招募数量

### 4.1 核心规则

C++ 核心已经接受任意正整数兵力，本次保留现有招募成本、人口和控制权规则：

- 输入必须是64位有符号整数范围内的正整数；
- 招募地区必须由招募国家实际控制；
- 招募数量不得超过地区可招募士兵；
- 招募数量不得超过地区总人口；
- 招募费用仍为每名士兵1资金；
- 国库必须足以支付全部费用；
- 成功后国库、可招募士兵和总人口同时减少对应数值；
- 新军队位于招募地区，初始移动点为0；
- 新军队取得本国最小空缺编制编号；
- 新军队没有推进目标，推进默认启用，策略默认是最大推进。

任何校验失败时，国库、人口、军队和编号占用情况都不得改变。

### 4.2 界面流程

地区管理窗口中的“招募军队”不再直接招募固定1000人，而是打开或展开招募输入区。输入区显示：

- 当前可招募士兵；
- 当前国库；
- 按兵源与国库计算的最大可招募数量；
- 招募数量输入框；
- “确认招募”和“取消”按钮；
- 操作状态或错误说明。

输入框只接受十进制整数。空输入、非整数、零、负数、超过64位范围或超过核心限制的数值不得提交。界面校验用于及时提示，C++ 核心仍执行最终校验。

招募成功后关闭或重置输入区，刷新地区人口、可招募士兵、国库、军队列表和地图军队标记。取消操作不调用核心命令。

## 5. 军队更名

### 5.1 命令

新增：

```text
RenameArmyCommand(army_id, formation_number)
```

命令必须满足：

- 军队存在；
- 新编号是正整数；
- 同国其他现存军队未使用该编号。

把军队改为其当前编号视为成功的幂等操作，状态不发生实质变化。若编号与同国另一支军队重复，则整条命令被拒绝。

成功事件至少包含军队稳定 ID、所属国家、旧编号和新编号，使界面可以生成明确反馈。

### 5.2 界面

地区管理窗口的军队详情区显示完整名称和内部稳定 ID。新增：

- “新军队编号”整数输入框；
- “更名”按钮。

玩家只输入 `X`，不能修改国家代号、“第”或“军”。操作成功后刷新该地区军队列表、推进计划列表、地图军队文字和行动反馈。

## 6. 军队合并

### 6.1 合法条件

新增：

```text
MergeArmiesCommand(primary_army_id, merged_army_ids)
```

其中主军是合并后保留的军队，`merged_army_ids` 是被吸收并删除的军队集合。

执行时必须重新校验：

- 主军存在；
- 至少有一支被合并军队；
- 输入列表中没有重复稳定 ID；
- 被合并列表不包含主军；
- 所有军队仍然存在；
- 所有军队属于同一个国家；
- 所有军队位于同一个地区；
- 合并后的兵力相加不会发生64位整数溢出。

任一条件失败时，整次合并被拒绝，不允许部分合并。

### 6.2 合并结果

成功合并后：

- 保留主军的稳定 ID；
- 保留主军的编制编号和完整显示名称；
- 保留主军的位置；
- 保留主军的自动推进目标、启用状态和推进策略；
- 主军兵力变为所有参与军队兵力之和；
- 主军移动点变为所有参与军队移动点的最小值；
- 被合并军队从游戏状态中删除；
- 被删除军队的编制编号立即释放，可被后续招募或更名使用。

移动点采用最小值，防止玩家通过把低移动力军队并入高移动力军队绕过移动限制。被合并军队的推进计划不转移。

成功事件至少包含主军 ID、被删除军队 ID 列表、合并前后兵力和合并后移动点。

### 6.3 界面流程

地区管理窗口增加“合并军队”区域：

1. 当前军队选择器中的军队作为主军；
2. 候选列表只显示同地区、同国家的其他军队；
3. 玩家可选择一支或多支候选军队；
4. 界面预览合并后的完整名称、总兵力和移动点；
5. 玩家点击“确认合并”；
6. 核心重新校验并执行；
7. 成功后刷新军队列表、管理窗口、地图和推进计划。

没有主军、没有候选或未选择被合并军队时，“确认合并”不可用。界面筛选不替代核心校验，因为候选军队可能在操作提交前移动或被消灭。

## 7. 数据模型与 API

### 7.1 数据模型

`Country` 新增：

```cpp
std::string code;
```

`Army` 新增：

```cpp
std::int64_t formation_number{};
```

`GameState` 提供按国家检查编号占用、寻找最小空缺编号和获取军队显示名所需的查询。编号分配与唯一性属于核心状态规则，不在 Godot 脚本中实现。

### 7.2 桥接 API

现有 `recruit_army(country_id, province_id, manpower)` 参数已经支持自定义数量，保留签名。

新增 Godot API：

```text
rename_army(army_id, formation_number) -> Dictionary
merge_armies(primary_army_id, merged_army_ids) -> Dictionary
```

军队查询结果新增：

- `formation_number`：整数；
- `display_name`：组合后的中文名称；
- `country_code`：国家代号，便于其他视图使用。

国家查询结果新增 `code`。

## 8. 存档与数据兼容

### 8.1 新游戏数据

`countries.json` 为每个国家新增 `code`。数据 schema 版本随之提升。加载时拒绝缺失、空白或重复的国家代号。

### 8.2 存档

新存档保存：

- 每个国家的 `code`；
- 每支军队的 `formation_number`。

存档加载完成后验证：

- 所有编制编号为正整数；
- 同国现存军队编号没有重复；
- 不要求跨国编号唯一。

对于本功能之前、仍被兼容策略允许读取的存档：按国家分别处理军队，以稳定 ID 的字典序排列，并从1开始依次分配编制编号。该迁移只发生在缺少 `formation_number` 时。国家代号若缺失，则根据当前剧本中同 ID 国家的代号补充；找不到对应国家代号时拒绝加载，避免生成含义不明或重复的名称。

内部全局 `next_army_sequence` 继续只负责生成稳定 ID，不替代各国编制编号分配。

## 9. AI 行为

AI 继续使用现有固定招募批次和招募决策，不需要新增输入界面。AI 招募的新军队与玩家军队使用相同的最小空缺编号规则。

首版 AI 不主动更名或合并军队。这两个命令仍是通用核心命令，后续可由 AI 规划器调用。

## 10. 错误处理与原子性

招募、更名和合并都通过 `CommandProcessor` 的临时工作状态执行。失败不得提交部分状态。

桥接层返回统一结果字典，至少包含 `accepted` 和 `error`；成功时附带新名称、编号或合并摘要。GDScript 将核心错误转换为中文提示，但不根据英文错误文本推导规则。

界面刷新时若当前选中的军队已因战斗或合并消失，应清除选择，并选择仍存在的合理默认军队；不得保留悬空稳定 ID。

## 11. 测试范围

### 11.1 C++ 核心测试

- 招募任意合法正整数兵力；
- 拒绝零、负数、兵源不足、人口不足和国库不足；
- 同国军队依次取得第1军、第2军；
- 编号空缺后招募复用最小空缺；
- 不同国家允许相同编号；
- 更名成功、幂等更名和同国冲突拒绝；
- 两支及多支军队合并；
- 合并后兵力求和、移动点取最小值、主军推进计划保留；
- 异国、异地、重复 ID、缺失军队和溢出合并被原子拒绝；
- 被合并编号释放并可再次使用；
- 战斗消灭军队后编号可再次使用；
- 新字段存档往返与旧存档迁移；
- 无效或同国重复编号存档被拒绝。

### 11.2 Godot 集成与界面测试

- 招募输入区的打开、取消、合法输入和非法输入；
- 招募数量正确传递到桥接层；
- 国家和军队查询包含代号、编号和完整名称；
- 更名成功与冲突提示；
- 合并候选只包含同国同地军队；
- 多选合并、预览和成功后的选择刷新；
- 军队列表、地图标记和推进计划统一使用完整显示名称；
- 保存、读取后名称、编号和合并结果不变。

## 12. 文档同步

功能实现后更新：

- `docs/current-game-rules.md`：替换固定1000人界面规则，加入编号、更名、合并和存档规则；
- `docs/project-structure.md`：记录新增命令、系统职责、场景/脚本或测试文件；
- `README.md`：只有当玩家可见功能概览需要调整时才更新。

## 13. 不在本次范围

- 自由文本军队名称；
- 修改国家代号的玩家界面；
- 军队拆分；
- 跨地区或跨国家合并；
- 合并时混合或选择被吸收军队的推进计划；
- 师、军、集团军等组织层级；
- 兵种、装备、补给、组织度、士气和维护费；
- AI 主动更名或合并。
