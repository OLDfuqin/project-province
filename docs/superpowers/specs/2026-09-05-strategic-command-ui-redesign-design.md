# 战略指挥台主界面重构设计

## 状态

- 设计日期：2026-09-05
- 设计状态：视觉方向已由用户批准，等待本文档复核
- 目标平台：Windows；同时为后续 Android、鸿蒙适配保留响应式结构
- 参考样图：[战略指挥台界面概念图](../../assets/ui/2026-09-05-strategic-command-ui-concept.png)

## 背景

当前主界面已经能够完整承载地图、回合推进、存档、订单、外交、道路建设、地区信息和地区管理，但这些不同层级的信息被同时放入右侧区域。实际运行检查表明，界面没有发生几何重叠，却存在以下体验问题：

- 地图、全局状态、低频系统操作和当前地区操作同时争夺注意力。
- 右侧上半部分是长滚动信息区，下半部分又是独立功能工作区，形成两套滚动容器。
- 地区管理打开后只能使用较窄、较矮的区域，玩家需要频繁纵向滚动。
- 项目名称、核心版本、存档数量等非游戏决策信息长期占据首屏。
- 国家、外交、战争、订单、事件历史与地区操作缺少清晰的信息层级。
- 大量内容采用连续文字表达，数据之间缺少卡片、图标、颜色和留白形成的视觉区分。

本次重构将主界面从“功能全部陈列”调整为“地图优先、按上下文渐进展示”。

## 设计目标

1. 地图始终是主游戏页面的视觉和操作中心，占据大部分可用空间。
2. 下一回合、日期和核心国家资源始终可见，但不挤压地图操作。
3. 同一时间只显示一个主要上下文页面，避免多个功能区同时展开。
4. 将低频操作、详情报告和历史记录移出首屏，但保持两次点击内可达。
5. 建立可复用的 Godot Theme、卡片、数据指标、页签和导航组件，为后续系统扩展提供稳定接口。
6. 在 1280×720、1440×900 和 1920×1080 下都不重叠、不截断，必要时通过折叠和滚动降级。
7. 不改变模拟核心、订单规则、回合规则和存档数据；本次只调整界面结构与表现。

## 非目标

- 不在本次重构中修改订单创建和结算时间。
- 不新增经济、外交、建筑、装备或战斗玩法。
- 不将概念图中的装饰性地图细节直接视为新游戏规则。
- 不复制参考开源项目的代码、美术、字体或商标资源。
- 不在第一轮实现时代主题皮肤切换，只建立可扩展的主题变量。

## 开源项目参考结论

本设计参考以下开源项目的公开界面和代码组织经验：

- OpenVic：Godot 界面、桥接层和原生模拟层分离，技术路线与本项目最接近。
- Freeciv-web：地图画布、单位/状态面板和国家、科技、城市等报告页分离。
- OpenDoctrines：通过人口、工业、防御、关系、军队等地图模式表达复杂数据。
- Sovereign：使用可切换地图覆盖层与可开关的地块检查器，避免地图常驻信息过量。
- Unciv：优先轻量、可扩展和跨桌面/移动端的界面结构。

这些项目只提供设计模式参考。本项目的视觉资产必须自行制作或使用许可证明确、兼容项目用途的资源。

## 总体信息架构

主界面由五个稳定区域组成：

```text
┌─────────────────────────────────────────────────────────────┐
│ 全局状态栏：国家、财政、人力、日期、下一回合                 │
├────┬──────────────────────────────────────┬─────────────────┤
│主导│                                      │                 │
│航栏│              战略地图                │  上下文检查器   │
│    │                                      │                 │
├────┴──────────────────────────────────────┴─────────────────┤
│ 地图模式、待执行订单、通知、回合报告                         │
└─────────────────────────────────────────────────────────────┘
```

### 全局状态栏

高度基准为 56 像素，横跨窗口顶部。常驻内容为：

- 当前玩家国家徽记、国家名称或短代号。
- 国库。
- 本月财政收入。
- 上月或预计军队维护费。
- 全国可招募士兵。
- 当前年月。
- “进入下一回合”主按钮。

下一回合按钮固定在最右侧，使用黄铜金主色，不随其他窗口和滚动区域移动。当存在财政赤字、无法执行的订单或其他阻塞时，在按钮左侧显示警告标记；按钮文字仍保持稳定。

项目名称、核心版本、地区数量和存档数量不放在状态栏中，迁入主菜单或设置页面。

### 主导航栏

左侧基准宽度为 64 像素，提供国家、外交、科技、军事、经济和设置入口。默认只显示统一风格的 24 像素图标，悬停时显示中文提示；高分辨率下可选展开文字，但展开不是第一版要求。

选择国家、外交、科技、军事或经济后，进入对应的完整管理页面。这些页面覆盖地图内容区，但保留全局状态栏和主导航栏，使玩家能够随时返回地图。设置以模态页面显示。

### 战略地图

地图占据主界面的最大区域，并继续支持左键选择、中键拖动和滚轮缩放。地图内部不常驻显示长文字，仅显示已有城市、首都、地形和军队图标。

地图新增以下表现状态：

- 悬停地区：浅色细边框与小型浮动提示。
- 选中地区：黄铜金双层轮廓。
- 可移动地区：低透明度蓝色覆盖。
- 可攻击地区：低透明度红色斜纹或红色边框。
- 修路合法目标：绿色轮廓。
- 修路非法目标：不高亮；悬停时在检查器中给出原因。
- 当前路径：细道路曲线或连接线，并显示移动点/费用摘要。

地图模式位于底栏，不在地图内部继续增加永久工具条。第一阶段实现政治、地形、军事和道路四种模式；经济模式保留入口，在相关数据展示就绪后启用。

### 上下文检查器

右侧只有一个完整高度的上下文检查器，不再保留“上方全局长列表 + 下方功能窗口”的双区域结构。

检查器有以下互斥状态：

- `empty`：没有选中对象，显示简短的新手提示和近期重要通知。
- `province_summary`：单击地区后的精简地区卡片。
- `province_management`：双击地区或点击“管理地区”后的完整地区管理。
- `army_management`：直接选择军队后的军队操作页面。
- `road_construction`：进入修路模式后的道路工具页面。

切换状态时替换检查器内容，不在旧内容下方继续追加。点击地图空白处只关闭临时地区摘要；地区管理、军队管理和修路模式必须通过关闭、返回或切换主功能退出，避免误操作丢失输入。

### 底部状态栏

基准高度为 44 像素，内容分为两组：

- 左侧：政治、地形、经济、军事、道路地图模式。
- 右侧：待执行订单数量、通知数量、回合报告入口。

订单、通知和回合报告使用底部抽屉。抽屉默认收起，展开后覆盖地图下部，但不覆盖全局状态栏和右侧检查器；再次点击入口或按 `Esc` 收起。同一时间最多展开一个底部抽屉。

## 页面与交互设计

### 地区摘要

单击地区后显示：

- 地区名称、城市/首都图标和国家色条。
- 法理国家与实际控制国家。
- 地形、道路状态。
- 人口、经济、财政收入、可招募士兵。
- 驻军数量与总兵力。
- “管理地区”按钮。

内容采用 2×2 数据指标卡与少量状态行，不重复显示同一数据，也不提供征兵、科技等复杂表单。

### 地区管理

地区管理在同一个右侧检查器内使用页签：

- 概况：地区核心数据、法理、控制权、道路和近期变化。
- 军事：征兵订单、驻军选择、军队调动、自动推进、合并和更名。
- 建设：道路入口，以及后续经济投资、民生投资和建筑功能。
- 订单：只显示与当前地区直接相关的待执行订单及取消操作。
- 历史：占领、战斗、人口和经济变化；在历史数据系统完成前隐藏该页签。

页签只控制展示，不复制核心状态。所有费用、可招募上限、移动目标和错误原因继续使用桥接层权威结果。

### 军队管理

军队页面显示可见名称、编制号、兵力、位置、移动点、当前订单和推进计划。主要操作按优先级排列：

1. 选择移动/进攻目标。
2. 设置或暂停自动推进。
3. 合并军队。
4. 更名。

选目标时检查器保持可见，地图切换到目标选择状态。确认目标后回到军队页面并显示已创建的订单卡片；创建订单不会让界面模拟额外推进一个回合。

### 道路建设

进入道路模式后，右侧检查器显示起点、终点、权威报价、科技要求和确认按钮。地图只高亮合法候选地区。建设订单提交成功后清空起点与终点并保留道路模式，方便连续规划；玩家可使用“重置”和“退出修路”按钮。

### 国家、外交、科技、军事和经济页面

这些是全尺寸管理页面，不强行放入右侧检查器：

- 国家：全国人口、财政、领土、可招募士兵和关键趋势。
- 外交：国家列表、关系状态、战争、宣战和议和操作。
- 科技：树形科技或分支科技页面、等级、费用、耗时和当前研究订单。
- 军事：全国军队列表、集团筛选、战线和待执行军事订单。
- 经济：收入、维护费、地区贡献和后续投资概览。

第一轮重构只迁移当前已有功能，不为尚未实现的系统制造可操作假按钮。未实现页面可以显示明确的只读规划占位，但默认不进入玩家主流程。

## 视觉系统

### 色彩令牌

| 用途 | 色值 |
| --- | --- |
| 主背景 | `#0B1220` |
| 一级面板 | `#111B2E` |
| 浮起卡片 | `#18243A` |
| 边框与分隔 | `#2B3B55` |
| 主文字 | `#E8EEF7` |
| 次要文字 | `#95A5BA` |
| 主操作/选中 | `#D6A64A` |
| 普通操作 | `#4C8DFF` |
| 警告/战争 | `#D85B5B` |
| 成功/完成 | `#4FB69F` |

国家颜色只用于地图领土、国家色条和少量身份标识，不替代操作状态色。

### 字体与字号

- 中文字体优先使用许可证明确的思源黑体或 Noto Sans CJK。
- 页面标题：24 像素，半粗体。
- 区块标题：16 像素，半粗体。
- 正文与按钮：14 像素。
- 辅助说明：12 像素。
- 关键数字可使用等宽或窄体数字字形，但中文与数字必须保持基线一致。

正文不使用全大写英文，不依赖颜色单独传达状态。

### 尺寸与间距

- 使用 8 像素基础间距体系，允许 4、8、12、16、24 和 32 像素组合。
- 常规按钮高度 36 像素，主按钮高度 40 至 44 像素。
- 卡片圆角 6 至 8 像素。
- 边框默认 1 像素；选中状态最多 2 像素。
- 阴影轻微且统一，不使用大面积发光。
- 面板使用不透明或高不透明背景，不采用影响文字可读性的玻璃模糊。

### 动效

- 检查器内容切换：120 至 160 毫秒淡入。
- 底部抽屉展开：160 至 200 毫秒平移。
- 按钮悬停：颜色或亮度变化，不进行明显缩放。
- 地图高亮：立即响应；不使用妨碍连续操作的长动画。

所有动效只用于说明状态变化，不阻塞输入。

## 响应式规则

### 1280×720

- 左侧导航保持 56 至 64 像素，只显示图标。
- 右侧检查器宽度为 320 像素。
- 顶栏可招募士兵等指标使用紧凑图标与数值。
- 地区管理内部允许单一纵向滚动，但顶栏、页签和主操作按钮固定。
- 底部抽屉最大高度不超过窗口的 40%。

### 1440×900

- 作为第一阶段视觉验收基准。
- 左侧导航 64 像素，右侧检查器 360 像素。
- 地区指标以 2×2 卡片展示。

### 1920×1080 及以上

- 右侧检查器可扩展至 400 至 420 像素。
- 顶栏显示完整文字标签。
- 不无限放大按钮和字体，额外空间优先提供给地图。

窗口低于 1280×720 时不保证完整桌面布局；未来移动端将采用独立断点和底部导航，而不是继续压缩桌面侧栏。

## Godot 组件边界

建议把当前单一场景中的界面拆成以下可复用组件：

- `StrategicShell`：统一布局、页面切换和响应式尺寸。
- `GlobalStatusBar`：国家资源、日期和下一回合。
- `PrimaryNavigation`：左侧主功能导航。
- `MapModeBar`：地图模式与图层状态。
- `ContextInspector`：管理互斥的上下文页面。
- `ProvinceSummaryPanel`：地区摘要。
- `ProvinceManagementPanel`：地区管理页签容器。
- `ArmyManagementPanel`：军队详情与订单操作。
- `RoadPlanningPanel`：修路状态机与报价展示。
- `BottomDrawer`：订单、通知和回合报告的通用抽屉。
- `MetricCard`、`StatusChip`、`OrderCard`：通用展示组件。

`main.gd` 负责连接桥接层、全局页面状态和地图选择，不继续负责每个控件的文本拼装。各组件只接收已经序列化的字典或明确参数，并通过信号提交用户意图。任何规则判断、费用计算和可执行性仍由 C++ 核心及桥接层决定。

## 状态切换规则

- 单击地区：`empty/other summary -> province_summary`。
- 双击地区或点击管理：`province_summary -> province_management`。
- 单击军队图标：`any temporary inspector -> army_management`。
- 点击修路地图模式：`any inspector -> road_construction`。
- 点击主导航：关闭底部抽屉和临时检查器，进入完整管理页面。
- 点击地图入口或按返回：关闭完整管理页面，恢复上一次地图选中状态。
- 点击订单、通知或回合报告：只切换底部抽屉，不改变当前地图选择和检查器。
- 按 `Esc`：优先关闭确认弹窗，其次关闭底部抽屉，其次退出目标选择/修路状态，最后打开设置菜单。

## 错误、加载和空状态

- 场景加载期间地图区域显示统一加载层，下一回合和会改变状态的操作禁用。
- 桥接错误显示为检查器内的中文错误条或底部通知，不恢复原始英文异常文本。
- 空订单、空驻军、无战争等状态使用一句简短说明，不保留大面积空卡片。
- 费用不足、移动目标非法等可预期拒绝不使用模态弹窗。
- 宣战、议和、取消已有进度的研究等高影响操作使用确认弹窗。
- 所有异步或跨回合订单在提交后立即显示订单 ID、预计完成时间和取消条件。

## 输入与可访问性

- 所有图标按钮必须提供中文 tooltip。
- 主操作按钮支持键盘焦点，并具有清晰的焦点边框。
- 不通过红绿颜色单独表示合法与非法，同时配合图标和文字。
- `Enter` 可确认当前聚焦的主要操作，`Esc` 按既定层级返回。
- 地图模式和主导航在后续可以增加可配置快捷键；首版不硬编码与 Godot 编辑器冲突的快捷键。
- 字号和关键点击目标在桌面端不得因窗口缩小低于设计下限。

## 迁移顺序

### 第一阶段：界面壳与主题

- 建立 Theme 资源、色彩令牌、字体、按钮、面板、页签和滚动条样式。
- 建立全局状态栏、主导航、地图容器、单一检查器和底栏。
- 把现有地图和下一回合功能迁入新壳，保持功能行为不变。

### 第二阶段：上下文页面

- 迁移地区摘要、地区管理、军队管理和道路建设。
- 删除旧的双右栏、旧内联道路控件和重复文字区域。
- 保持已有单击、双击、移动目标和修路状态机测试。

### 第三阶段：抽屉与完整管理页

- 迁移待执行订单、通知、事件历史和回合报告到底部抽屉。
- 建立国家、外交、科技、军事、经济页面，先迁移现有能力。
- 把快速保存和读取迁入设置菜单，同时保留明确快捷入口。

### 第四阶段：地图表现与打磨

- 完成地图模式、高亮、路径表现和 tooltip。
- 加入短动效、声音反馈占位和高分辨率适配。
- 进行完整视觉回归和实机试玩调整。

每个阶段必须保持游戏可运行，不允许先删除旧入口再等待后续阶段补回。

## 验收标准

1. 1280×720、1440×900、1920×1080 三种分辨率下无控件重叠或不可达操作。
2. 主页面地图占据除导航、检查器和状态栏外的全部空间，1440×900 下有效地图区域明显大于现状。
3. 右侧不存在两个同时可滚动的顶级业务面板。
4. 下一回合按钮在所有地图上下文状态下始终可见。
5. 从地图选择地区到征兵、军队调动或修路的操作不超过现有点击次数。
6. 快速保存、读取、外交、科技、订单、回合报告仍然可达且没有功能丢失。
7. 订单、报价、移动范围和错误原因全部来自桥接层权威数据，UI 不复制核心公式。
8. 所有新增玩家可见文字为中文，不出现占位英文和内部稳定 ID。
9. 地区摘要、地区管理、军队管理、道路建设和底部抽屉的互斥/返回行为有自动化测试。
10. 主场景启动、现有 Godot 测试、核心测试和截图视觉检查全部通过。

## 设计风险与控制

- `main.gd` 当前职责过多：迁移时按组件逐步抽离，避免一次性重写所有业务连接。
- 概念图的地图细节高于当前资源水平：第一阶段只实现布局、主题和状态视觉，不把装饰当成阻塞条件。
- 完整管理页面会增加导航状态：使用单一页面路由和明确返回规则，禁止组件自行切换全局页面。
- 响应式布局可能影响现有坐标测试：测试应以节点、信号和容器约束为主，截图只用于视觉回归。
- 开源参考项目许可证不同：不直接复制代码和素材，新引入资产必须登记来源与许可证。

## 最终决策

采用“深色军政指挥台”视觉风格，以全屏战略地图为底座，使用顶部全局状态栏、左侧主导航、单一右侧上下文检查器和底部地图模式/信息抽屉。该设计替代当前双右栏结构，并作为未来经济、建筑、兵种、装备、战线和更复杂外交系统的统一界面基础。
