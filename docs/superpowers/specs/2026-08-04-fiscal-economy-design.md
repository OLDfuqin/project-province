# 人口经济与财政收入系统设计

## 目标

用“人口派生经济 + 地形修正财政收入”替代当前地区 JSON 中的固定经济值，使人口增长、征兵、科技和领土控制能够自动改变国家经济与国库收入。

本次只改造已经存在的经济与收入循环，不加入税率、投资、建筑、维护费或其他尚未实现的经济系统。

## 核心公式

### 地区经济

设：

- `population` 为地区当前总人口；
- `economy_level` 为用于该地区计算的国家经济科技等级，范围0至3；
- `technology_percent = 100 + 10 × economy_level`。

则：

```text
地区经济 = floor(population × technology_percent / 100)
```

经济科技只改变地区经济，每级使经济增加10%。

### 地区财政收入

财政收入由地区经济、固定1%收入率和地形系数共同决定：

| 地形 | 地形系数 | 整数分子 |
|---|---:|---:|
| 平原 | 1.0 | 100 |
| 森林 | 0.9 | 90 |
| 丘陵 | 0.9 | 90 |
| 山地 | 0.8 | 80 |

精确公式为：

```text
地区财政收入 = floor(地区经济 × 地形系数分子 / 10000)
```

`10000` 同时包含百分之一收入率的分母100和地形百分比的分母100。只在公式末尾向下取整一次，不先对1%收入取整。

示例：人口120000、经济科技1级、森林地区：

```text
地区经济 = floor(120000 × 110 / 100) = 132000
地区财政收入 = floor(132000 × 90 / 10000) = 1188
```

### 国家合计

```text
国家经济总和 = 该国实际控制的所有地区经济之和
国家财政收入总和 = 该国实际控制的所有地区财政收入之和
```

月度结算向国库加入财政收入总和，不把经济总和直接加入国库。

## 控制权临时规则与优先问题

本版本沿用现有收入归实际控制者的规则：

- 地区采用当前实际控制国的经济科技计算地区经济；
- 地区经济与财政收入计入当前实际控制国；
- 法理所有者在失去实际控制后不获得该地区财政收入。

这会导致占领发生时，地区经济可能因为控制国科技不同而立即变化。该行为必须在 `docs/current-game-rules.md` 中使用醒目标记说明，并标记为后续优先解决的逻辑问题；本次不设计最终的占领区科技、税制或经济损害模型。

## 单一计算来源

采用完全派生方案，不缓存地区经济和财政收入。

`EconomySystem` 提供只读计算入口：

```cpp
static std::int64_t province_economy(
    const GameState& state,
    const ProvinceId& province_id
);

static std::int64_t province_fiscal_income(
    const GameState& state,
    const ProvinceId& province_id
);
```

两个函数都按地区实际控制者查找经济科技。月度结算、Godot 地区摘要和国家摘要必须调用同一入口，禁止在界面层复制公式。

所有中间计算使用非负整数的溢出安全乘除。若状态数值无法表示派生结果，核心抛出溢出错误，不产生回绕后的负数。

## 数据模型与版本

### 删除旧经济字段

彻底删除以下固定字段：

- `Province::economy`；
- `game/data/provinces.json` 中每个地区的 `economy`；
- 存档地区记录中的 `economy`；
- 所有以固定地区经济值为输入的加载和验证代码。

不保留兼容字段或默认值，防止固定值与派生值形成两个事实来源。

### 结构版本

- `countries.json` 与 `provinces.json` 的剧本结构版本升至3；
- `ScenarioLoader` 支持版本改为3；
- `map_geometry.json` 仍是独立的地图几何结构版本2；
- 存档结构版本升至3；
- 旧版本2存档明确拒绝读取，不做迁移。

## 核心事件与桥接语义

为避免继续把“经济”和“财政收入”混为一谈：

- `CountryIncome` 重命名为 `CountryFiscalIncome`；
- `MonthlyEconomyReport` 重命名为 `MonthlyFiscalReport`；
- `GameEventType::economy_resolved` 重命名为 `fiscal_income_resolved`；
- `EconomyResolvedEvent` 重命名为 `FiscalIncomeResolvedEvent`；
- Godot 回合结果字段 `incomes` 重命名为 `fiscal_incomes`；
- 回合日志显示“财政收入”，不再只显示“收入”。

事件仍由现有 `EconomySystem` 生成，因为该系统同时负责经济派生和财政结算。

## 界面展示

### 国家主页面

每个国家条目同时显示：

```text
国家名 · 国库 N · 控制地区 N · 经济 N · 财政收入 N · 科技……
```

经济与财政收入都按当前控制地区实时汇总。这里的财政收入表示按当前状态计算的单月收入，不是上一回合历史收入。

### 地区窗口

地区信息窗口和地区管理窗口都显示：

- 当前地区经济；
- 当前地区单月财政收入。

人口增长、征兵、科技研究、占领、议和和读取存档后刷新所有相关显示。

## 月度结算影响

月度顺序保持不变：财政收入仍在当月人口增长之前结算。

因此：

- 本月人口增长从下个月开始提高财政收入；
- 本月 AI 或玩家研究经济科技，从下个月财政结算开始生效；
- 回合开始前已完成的征兵会立即降低下一次财政收入；
- 回合开始前已经形成的占领会按占领国科技计算当月收入。

## 测试要求

### C++ 核心

覆盖：

1. 四种地形的经济与财政公式；
2. 经济科技0至3级对经济的10%递增；
3. 只在财政公式末尾向下取整；
4. 国家月度国库只增加财政收入；
5. 人口增长在下一月改变经济与财政；
6. 招募扣除人口后降低经济与财政；
7. 占领区使用实际控制国科技并向控制国纳税；
8. 剧本不再需要固定经济字段；
9. 存档版本3往返保存不包含固定经济字段；
10. 版本2存档被拒绝。

### Godot 与界面

覆盖：

1. 地区摘要同时暴露 `economy` 和 `fiscal_income`；
2. 国家摘要暴露经济总和和财政收入总和；
3. 主页面显示两个国家合计；
4. 地区信息与管理窗口显示两个地区值；
5. 回合响应使用 `fiscal_incomes`；
6. 现有布局在较大数字下不扩张或重叠。
