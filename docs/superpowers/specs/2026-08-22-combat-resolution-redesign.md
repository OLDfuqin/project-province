# 战斗结算系统重构设计

日期：2026-08-22  
状态：已确认设计，等待实施计划

## 1. 目标

本轮更新重构军队进入敌军所在地区后的战斗结算，覆盖有效战力、随机波动、伤亡、胜负、撤退、歼灭、占领和战报。

本轮采用“独立战斗计算器 + 状态执行器”结构：纯计算模块负责产生可验证的战斗结果，现有 `BattleSystem` 负责把结果应用到军队和地区状态。该边界为后续兵种、装备、士气和更复杂战斗阶段预留扩展位置，但本轮不实现这些内容。

## 2. 参战范围

- 进攻方只包含当前进入目标地区的那一支军队。
- 防守方包含目标地区内所有与进攻国交战的外国军队。
- 同地区的其他进攻方军队不加入本次进攻。
- 防守方以所有参战军队的总兵力作为一个整体计算有效战力和总伤亡。
- 无防守军队时不抽取随机数、不产生伤亡，进攻军直接占领敌方控制地区。

## 3. 随机参数

每次实际战斗分别为进攻方和防守方独立抽取一次随机参数 `X`：

```text
X ∈ {0.7, 0.8, 0.9, 1.0, 1.1, 1.2, 1.3, 1.4}
```

正式游戏使用系统随机源。随机状态和随机种子不写入存档，因此读取同一存档后重复同一场战斗可能得到不同结果。

计算与展示使用十分位整数保存随机参数，例如 `7` 表示 `0.7`、`14` 表示 `1.4`，避免直接比较浮点随机值。

测试可以向独立战斗计算器注入固定随机结果，以稳定覆盖公式边界和胜负分支；该测试接口不改变正式游戏的随机规则。

## 4. 军事科技等级

进攻方军事等级为进攻军所属国的军事科技等级。

若防守方包含多个国家，防守军事等级按各国参战兵力加权平均并向下取整：

```text
防守军事等级 =
floor(Σ(各国参战兵力 × 该国军事等级) ÷ 防守总兵力)
```

同一国家的多支防守军可以先合并其兵力再参与加权，结果不变。

## 5. 有效战力

设：

- 进攻总兵力为 `A`；
- 防守总兵力为 `D`；
- `N = min(A, D)`；
- `M = max(A, D)`；
- 某一方独立抽取的随机参数为 `X`；
- 该方军事科技等级为 `L`。

兵力较少一方的基础有效战力：

```text
floor(X × N × (100 + 10 × L) ÷ 100)
```

兵力较多一方的基础有效战力：

```text
floor(X × N × sqrt(M ÷ N) × (100 + 10 × L) ÷ 100)
```

双方兵力相等时，两边都按兵力较少方公式计算；此时与兵力较多方公式中 `sqrt(M/N) = 1` 的结果一致。

进攻方和防守方分别代入自己的 `X` 与 `L`。公式中的 `N`、`M` 始终来自双方战前原始总兵力。

实现应避免中间乘法溢出，并明确在完整表达式计算结束后统一向下取整，不得在中间步骤提前截断平方根或科技倍率。

## 6. 地形防御加成

防守方保留现有地形防御加成。防守基础有效战力计算完成后，再计算最终防守有效战力：

```text
最终防守有效战力 =
floor(防守基础有效战力 × (100 + 地形防御加成) ÷ 100)
```

| 地形 | 防御加成 |
|---|---:|
| 平原 | 0% |
| 森林 | 10% |
| 丘陵 | 20% |
| 山地 | 30% |

进攻方不获得目标地区的地形加成。后续伤亡公式使用最终防守有效战力。

## 7. 伤亡

设进攻方有效战力为 `AS`，应用地形后的最终防守有效战力为 `DS`：

```text
进攻方伤亡 = min(A, max(1, floor(DS ÷ 2)))
防守方总伤亡 = min(D, max(1, floor(AS ÷ 2)))
```

由于实际战斗双方兵力均为正数，双方至少产生 `1` 人伤亡，且伤亡不会超过本方战前兵力。

### 7.1 多支防守军队的伤亡分配

防守方总伤亡按各防守军战前兵力比例分配：

```text
某军精确份额 = 防守方总伤亡 × 该军战前兵力 ÷ 防守总兵力
```

分配采用最大余数法：

1. 每支军队先取得精确份额的整数部分；
2. 计算尚未分配的伤亡人数；
3. 按小数余数从大到小逐一补发 `1` 人伤亡；
4. 小数余数相同时按稳定军队内部 ID 升序处理。

分配结果必须满足：

- 每支军队伤亡不超过其战前兵力；
- 各军伤亡之和严格等于防守方总伤亡；
- 相同输入与相同随机参数得到完全相同的分配结果。

## 8. 胜负、撤退、歼灭与占领

伤亡全部计算并应用后，再根据双方剩余总兵力判断结果。

### 8.1 防守方仍有兵力

- 防守方胜利，与双方有效战力大小无关；
- 所有存活防守军留在战斗地区，不撤退；
- 进攻军若仍有兵力，则退回本次进攻的出发地区；
- 进攻军若兵力归零，则被删除；
- 地区控制权不变。

### 8.2 防守方归零且进攻方仍有兵力

- 进攻方胜利；
- 所有兵力归零的防守军被删除；
- 进攻军留在目标地区；
- 若目标地区尚不由进攻国控制，则将其设为进攻国占领。

### 8.3 双方同时归零

- 战斗结果记为双方同归于尽，不判定任何一方获胜；
- 双方兵力归零的军队全部删除；
- 地区保持战斗前控制权，不发生占领。

### 8.4 删除的旧规则

彻底删除“防守方战败后搜索相邻己方控制地区并撤退”的规则。`find_retreat_province` 不再参与战斗结算；若没有其他调用，应一并删除。

## 9. 计算结果与状态应用边界

新增独立的战斗计算输入与输出结构。输入至少包含：

- 进攻方总兵力及军事等级；
- 防守方各军的稳定 ID、兵力、国家和军事等级；
- 战场地形防御加成；
- 双方随机参数。

纯计算输出至少包含：

- 双方随机参数；
- 双方战前总兵力和用于计算的军事等级；
- 双方基础有效战力；
- 防守方最终有效战力和地形加成；
- 进攻方伤亡与剩余兵力；
- 防守方总伤亡、剩余总兵力及逐军分配；
- 结果类型：防守胜利、进攻胜利或双方同归于尽。

计算器不得读取或修改 `GameState`。`BattleSystem` 收集输入、调用计算器，然后统一执行兵力扣减、军队删除、进攻方撤退和地区占领。应用过程中出现内部数据不一致时应抛出逻辑错误，不允许产生部分结算。

## 10. 桥接层与战报

现有战斗结果事件继续保留逐军伤亡信息，并新增以下字段：

- 进攻方与防守方随机参数 `X`；
- 双方战前参战兵力；
- 双方用于计算的军事科技等级；
- 双方基础有效战力；
- 防守方最终有效战力；
- 地形防御加成；
- 战斗结果类型；
- 双方总伤亡和剩余总兵力。

主界面即时战报和回合行动战报均显示：双方 `X`、参战兵力、军事等级、有效战力、地形加成、伤亡、剩余兵力、撤退或歼灭状态、胜负与占领结果。

显示层使用军队的玩家可见名称；内部事件继续使用稳定军队 ID 关联结果。

## 11. 存档与兼容

本轮不保存随机种子或随机状态，也不新增持久化战斗状态。战斗仍在军队进入地区时立即完整结算，因此不需要升级存档版本。

现有军队、地区占领和科技字段含义不变。旧存档加载后发生的新战斗直接使用新规则。

## 12. 测试范围

核心计算器测试至少覆盖：

- `X=0.7` 和 `X=1.4` 两个边界；
- 双方兵力相等；
- 进攻方为兵力较少方与较多方；
- 不同军事等级；
- 四种地形加成；
- 多国防守的加权军事等级向下取整；
- 多支防守军按最大余数法分配伤亡及 ID 同余数排序；
- 防守方存活、进攻方胜利、双方同归于尽三种结果；
- 大兵力输入的中间计算不会溢出。

系统与桥接测试至少覆盖：

- 防守方存活时原地坚守，进攻方撤回出发地区；
- 防守方归零时不再撤退，进攻军占领地区；
- 双方归零时均删除且地区控制不变；
- 无守军直接占领；
- 战报完整暴露随机参数、有效战力、伤亡和结果类型；
- 固定随机注入使测试结果可复现；
- 现有保存/加载、自动推进和回合行动测试不回归。
