# 项目文件说明文档设计

## 目标

将 `docs/project-structure.md` 扩展为仓库唯一的项目结构与文件职责说明，帮助开发者在不通读全部源码的情况下判断每层目录、每个受版本控制文件的用途，以及实现某类改动时应从哪里开始。

## 文档结构

文档按照“整体链路 → 根目录 → 模块目录 → 逐文件索引 → 生成物 → 修改导航 → 维护规则”的顺序组织。目录表说明层级职责，文件表说明单个文件的责任、主要依赖或修改时机。

当前有效结构以 Git 跟踪文件和实际构建配置为准。`build/`、`.vs/`、`game/.godot/` 等本地产物单独说明，不与源代码混列。`third_party/godot-cpp` 按 Git 子模块描述，`third_party/nlohmann` 按仓库内置第三方代码描述。

## 边界

- 本次只修改文档，不修改源码、场景、数据或构建行为。
- `docs/project-structure.md` 是结构职责的唯一正式来源；不另建重复的正式指南。
- `docs/current-game-rules.md` 继续作为当前玩法和计算公式的唯一正式来源。
- 历史设计与实施计划保留在 `docs/superpowers/`，不代表当前代码状态。
- 文档使用 UTF-8，并明确要求文件增删、移动或职责变化时同步维护。

## 验收标准

1. 所有 Git 跟踪的项目文件均能在文档中按文件名或明确的同类文件规则找到说明。
2. 根目录及主要子目录均有用途和提交策略说明。
3. 核心、桥接、Godot、数据、测试、脚本和第三方依赖的边界清楚。
4. 新开发者能通过“常见修改导航”定位经济、人口、军事、道路、外交、科技、AI、存档、UI、地图和数据改动入口。
5. 不包含未实现功能，也不把构建产物误写为源文件。
