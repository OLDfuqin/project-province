# 固定月度订单系统设计

## 目标

把即时征兵、修路、科技、移动和战斗改为可保存、可取消、按固定一个月统一结算的订单系统，并同步调整费用、维护费、军队行动成本、共同进攻和自动整编。

## 时间模型

- 一回合固定为一个月，`AdvanceTurnCommand` 只接受 `months == 1`。
- 玩家规划阶段提交订单；AI 在上一月结算完成后生成下月隐藏订单。
- 点击进入下一回合后依次执行：日期与常规月结算、普通移动、进攻战斗、项目进度、自动整编、AI 下月规划。
- 财政收入、人口与可招募人口增长、维护费和移动点发放每月执行一次。

## 费用与负债

- 征兵费用为每名士兵 4，替代原来的每名士兵 1。
- 科技费用为旧公式的 5 倍，即从当前等级 `L` 升级时支付 `5000 × (L + 1)`。
- 普通国家每月维护费为 `floor(全国军队总兵力 / 2)`；隐藏中立国免除维护费。
- 维护费允许国库降为负数。国库为负时禁止新建征兵、修路和研究订单；已付费订单继续推进。
- 财政收入直接进入国库，自然用于抵消负债；当前没有利息。

## 订单模型

`GameState` 保存稳定递增订单 ID 和强类型订单：

- 军队行动订单：军队、所有国、起点、目标、完整稳定路径、已预留半点移动点、是否进攻。
- 征兵订单：国家、地区、人数、费用、剩余 1 个月。
- 修路订单：国家、两端地区、费用、剩余 1 个月。
- 研究订单：国家、科技分支、原等级、目标等级、费用、剩余月份。

同一军队只能有一条行动订单；同一国家只能有一个研究订单。一个目标地区同月只能被一个进攻国家锁定，同一国家可追加多支进攻军队。待执行订单必须进入存档和状态校验。

## 资源预留与取消

- 项目下单时立即扣除资金。征兵人口只做预留，完成时才从总人口、可招募士兵和基础经济中正式扣除。
- 行动订单下单时立即扣除完整路径成本；进攻在此基础上额外扣除 2 移动点（内部为 4 个半点单位）。
- 玩家在推进回合前取消行动、征兵或修路订单时全额退款。研究在第一次月度推进前取消全额退款；已经推进后取消不退款。
- 系统在执行前重新校验路径、位置、通行、战争、控制权和工程条件。因外部局势失效时，全额返还未实际使用的资金、人口预留和移动点。
- 进攻目标变为己方控制时自动转为普通移动并退还额外进攻成本；普通移动目标变为敌方时取消并退款。
- 有行动订单的军队不能手动合并；更名仍然允许。

## 移动与战斗

- 玩家选择当前移动点能覆盖的任意合法目的地。路径中间只能经过己方实际控制地区；敌方地区只能作为最终目标。
- 普通路径每条边继续使用道路或目的地地形成本。进攻总成本为完整路径成本再加 2 点。
- 月度结算先执行全部普通移动，再处理进攻。因此撤离军队可离开，进入目标地区的友军可参加防守。
- 进攻按“进攻国家 + 目标地区”分组，同国多军临时合计为一个进攻集团。各参战军队仍保留稳定 ID 和编制；进攻方伤亡按参战兵力比例分配，余数按稳定 ID 处理。
- 守军仍按现行共同防守规则参战。每支实际参战守军扣除 1 移动点，允许最低降至 -1；后续移动点发放先偿还负值。
- 无守军时仍执行进攻占领并消耗全部预留成本。

## 项目完成与自动整编

- 征兵和修路均在一次月度推进后的项目阶段完成，不影响刚结束的军事结算。
- 研究到目标等级 `L` 需要 `L + 1` 个月；完成后的等级从下月军事行动开始生效。
- 项目阶段结束后，同国同地区所有兵力小于 1500 的军队按兵力升序、稳定 ID 升序配对合并，直到不足 1500 的军队少于两支。
- 合并保留较小编制编号，移动点取两军最低值，旧军队 ID 删除并释放其编制编号。

## AI

- AI 订单与玩家订单使用同一核心 API 和合法性规则。
- 每月结算完成后 AI 基于当时局势提交下月订单，不能读取玩家之后提交的订单。
- 敌方待执行订单不通过玩家桥接查询暴露。玩家只能查看己方订单。
- AI 不再在同一次 `advance_turn` 中即时行动；其订单至少等待到下一次月度推进。

## 界面与反馈

- 主回合栏删除 1/3/6/12 月选择框，按钮固定显示“进入下一回合（1个月）”。
- 地区管理窗口显示可达目的地、军队待执行订单、取消按钮、征兵订单和研究剩余月份。
- 修路窗口提交后显示“已下单，剩余1个月”，而不是立即出现道路。
- 命令响应区分“订单已创建”和“行动已完成”；月度战报按结算阶段显示维护、移动、战斗、项目完成、自动整编与订单失效退款。
- 国家摘要显示本月军队维护费和负债状态。

## 存档与兼容性

- 存档 schema 从 6 升级为 7，保存下一订单序号、全部订单字段、研究进度和人口预留。
- 读取时严格验证稳定 ID 引用、路径连续性、预留数值、唯一军队订单、唯一国家研究项目和目标进攻锁。
- schema 6 及更早存档拒绝读取，不做推测迁移。

## 验证范围

- 核心：费用、负债、维护、中立豁免、订单预留/取消/退款、固定月长、远程路径、移动先于战斗、共同进攻、守军移动债务、项目周期、自动整编、AI 延迟和状态校验。
- 存档：schema 7 往返、订单与进度恢复、非法订单拒绝。
- 桥接：订单创建/取消/查询、固定一个月结算和中文事件字典。
- Godot：移除月份选择、可达目的地选择、订单状态、研究倒计时、修路/征兵延迟和主场景无重叠。
